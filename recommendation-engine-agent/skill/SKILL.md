# Recommendation Engine

Use this skill when the user wants properties similar to a specific listing
and explicitly provides a listing ID.

## When to use this skill

Use this skill for requests such as:

- "Find listings similar to 123456."
- "Recommend properties similar to listing 123456."
- "I like listing 123456. Show me similar homes."
- "Show me alternatives to listing ID 123456."
- "Find properties like MLS listing 123456."

The user must provide a listing ID.

If the user does not provide a listing ID, do not invent or infer one. Explain
that this recommendation skill currently requires a listing ID.

Do not use this skill for ordinary property-search requests that only specify
preferences such as city, price, bedrooms, bathrooms, or amenities without a
target listing ID.

---

# Goal

Given a target listing ID:

1. Retrieve the target listing.
2. Load the target listing's saved embedding.
3. Retrieve active candidate listings.
4. Compare each candidate with the target listing.
5. Calculate the hybrid recommendation score.
6. Rank candidates from most similar to least similar.
7. Return the top recommended listings.
8. Validate recommendation prices using recent comparable sales when available.

---

# Recommendation Logic

The recommendation engine uses the project's existing hybrid similarity logic.

The hybrid score combines:

- Structured property similarity
- Semantic embedding similarity

Structured similarity may consider fields such as:

- Listing price
- Property type
- City
- Living area / square footage

Semantic similarity uses the saved listing embeddings generated from the
listing text and compares listings using cosine similarity.

Do not recalculate or replace the scoring logic inside the skill. Use the
existing recommendation-engine implementation.

---

# Embedding Data

The recommendation engine uses the pre-generated file:

```text
data/listing_embeddings.json
```

The embeddings are generated by:

```bash
npx tsx src/build-listing-embeddings.ts
```

The embedding file should already exist before this skill is used.

Do not rebuild the embedding file for every recommendation request.

---

# Execution

Extract the listing ID from the user's request.

Run the recommendation CLI from the recommendation-engine project directory:

```bash
npx tsx src/cli.ts "LISTING_ID"
```

Replace `LISTING_ID` with the actual listing ID supplied by the user.

Example:

User request:

```text
Find listings similar to 123456.
```

Run:

```bash
npx tsx src/cli.ts "123456"
```

Use the CLI output as the recommendation result.

---

# Output

Present the recommendation results clearly to the user.

Return the recommended active listings in the order produced by the
recommendation engine.

For each recommendation, include the useful fields returned by the CLI, such as:

- Listing ID
- Address, if available
- City
- Listing price
- Bedrooms
- Bathrooms
- Living area / square footage
- Property type
- Similarity score
- Comparable estimated price, if available
- Comparable sale count, if available
- Percentage difference from the comparable estimate, if available

Do not fabricate fields that are missing from the CLI output.

---

# Rules

- Only use this skill when the user provides a listing ID.
- Do not guess or invent a listing ID.
- Use the existing recommendation engine instead of implementing new scoring
  logic inside the skill.
- Only recommend listings returned by the recommendation engine.
- Do not return the target listing itself as a recommendation.
- Use active listings as recommendation candidates.
- Use `california_sold` only for comparable-sales validation when the existing
  recommendation pipeline does so.
- Do not expose raw embedding vectors.
- Do not expose SQL queries or internal implementation details unless the user
  explicitly asks for them.
- Do not describe comparable-sales estimates as professional appraisals.
- If the target listing ID cannot be found, clearly tell the user.
- If the target listing does not have a saved embedding, clearly report that
  the recommendation cannot be generated from the current embedding file.
- If no suitable recommendations are returned, say so rather than fabricating
  results.
- If comparable-sales data is unavailable or insufficient, still return the
  recommendation results and state that price validation is limited.

---

# Scope

This version of the skill supports only recommendation requests where the user
explicitly provides a listing ID.

It does not currently resolve:

- Property addresses into listing IDs
- Natural-language property descriptions into listing IDs
- References such as "the house I looked at earlier"

Those capabilities can be added later without changing the core recommendation
engine.
